# ML + LLM 2단계 이상 탐지: 로그 보안 분석

**카테고리:** devlog
**태그:** anomaly-detection, Isolation-Forest, LLM, security, logs
**프로젝트:** agents/01-aiops

---

## 요약

Isolation Forest로 "뭔가 이상하다"를 감지하고, LLM으로 "왜 이상한지"를 설명하는 2단계 파이프라인을 만들었습니다.

---

## 시작은 단순한 질문

Nginx 액세스 로그에서 공격 시도를 자동으로 찾을 수 없을까? 처음에는 규칙 기반으로 접근했습니다. 403 응답이 많은 IP를 필터링하고, 알려진 공격 UA를 차단하는 식이었습니다.

하지만 새로운 패턴이 나타날 때마다 규칙을 추가해야 했고, 곧 관리가 어려워졌습니다.

## 4단계 파이프라인

최종적으로 4단계 구조가 되었습니다.

1. **Ingester**: 로그를 JSON으로 구조화합니다 (IP, method, status, UA, timestamp)
2. **Detector**: Isolation Forest가 정상 패턴에서 벗어난 요청을 표시합니다
3. **Analyzer**: LLM이 이상 로그 묶음을 읽고 원인을 분석합니다
4. **Reporter**: 심각도와 권고사항을 Telegram으로 보냅니다

## 왜 ML만으로는 부족했나

Isolation Forest는 "이 요청 패턴이 비정상"이라고 알려줍니다. 하지만 그게 크롤러인지, 무차별 대입 공격인지, 단순 설정 오류인지는 모릅니다. 숫자만으로는 맥락을 알 수 없습니다.

LLM에 이상 로그를 넘기면 "이건 WordPress 플러그인 스캐너 봇이고, wp-admin 경로를 반복 탐색하고 있다"는 수준의 해석을 해줍니다.

## 왜 LLM만으로는 부족했나

반대로 모든 로그를 LLM에 넣으면 비용도 문제지만, 정상 트래픽 속에 숨은 미세한 이상을 놓칩니다. 하루 수만 줄의 로그에서 의미 있는 패턴을 찾으려면, ML이 먼저 후보를 추려줘야 LLM이 집중할 수 있습니다.

## Isolation Forest를 선택한 이유

보안 로그에 레이블을 다는 건 비현실적입니다. "이 요청은 공격", "이건 정상"을 일일이 태깅할 수 없습니다. Isolation Forest는 비지도 학습이라 레이블이 필요 없습니다. 정상 데이터의 분포를 학습하고, 거기서 벗어나면 이상으로 표시합니다.

## 배운 점

- ML과 LLM은 경쟁이 아니라 보완 관계였습니다. 각자 잘하는 영역이 달랐습니다
- 컨텍스트 윈도우 안에 들어갈 만큼만 추려서 넘겨야 LLM의 분석이 정확했습니다
- Telegram 알림은 구현이 단순하지만, 즉각적인 대응을 가능하게 해주어서 가성비가 매우 좋았습니다
