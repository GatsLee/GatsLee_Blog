# git log에서 블로그 포스트 자동 생성하기

**카테고리:** devlog
**태그:** automation, git, LLM, content-generation, agents
**프로젝트:** agents/02-blog

---

## 요약

git 커밋 히스토리를 파싱해서 LLM으로 블로그 초안을 만들고, SEO 메타데이터까지 자동 생성하는 에이전트를 만들었습니다.

---

## 커밋은 하는데 글은 밀린다

매일 코드를 짜고 커밋을 합니다. 하지만 블로그에 그 과정을 정리하는 건 자꾸 밀렸습니다. 커밋 메시지에는 이미 뭘 했는지가 요약되어 있는데, 이걸 자동으로 글로 만들 수 없을까 하는 생각이 들었습니다.

## 3개 파이프라인

블로그 에이전트는 세 가지 파이프라인으로 구성했습니다.

**Pipeline 1 - 콘텐츠 생성**

1. GitPython으로 최근 커밋을 파싱합니다 (diff, message, 변경 파일)
2. 관련 커밋끼리 클러스터링합니다 (같은 기능이나 수정에 해당하는 것들)
3. LLM에 커밋 클러스터를 넘기고 블로그 초안을 받습니다
4. SEO 메타데이터(title, description, tags)를 자동 생성합니다
5. Blog API(`/api/posts`)로 draft 상태로 저장합니다

**Pipeline 2 - 운영 모니터링**

빌드 실패를 감지하고, LLM으로 원인을 분석한 뒤 Telegram으로 알립니다.

**Pipeline 3 - 트래픽 분석**

주간 인기 포스트를 집계하고 트렌드 리포트를 생성해서 Telegram으로 보냅니다.

## 커밋 → 블로그 변환

LLM에 넘기는 프롬프트는 이런 구조입니다.

```
다음 커밋 묶음을 기반으로 기술 블로그 글을 작성해주세요.
- 했습니다 체
- 2-3문장 요약으로 시작
- 문제 → 해결 → 배운 점 구조
- 코드 스니펫이 있으면 포함
```

커밋 메시지 컨벤션이 좋으면 LLM 초안 품질도 확 올라갔습니다. `[FEAT] add 3-layer RAG search`는 좋은 입력이지만, `fix stuff`는 LLM도 어쩔 수 없었습니다.

## 반자동이 현실적

처음에는 완전 자동 게시를 목표로 했습니다. 하지만 LLM이 생성한 글을 그대로 올리기엔 사실 확인이나 맥락 보충이 필요한 경우가 많았습니다.

결국 draft 상태로 저장하고, 사람이 검수한 뒤 publish하는 반자동 방식으로 바꿨습니다. 글쓰기의 가장 힘든 부분인 "빈 화면에서 시작하기"를 에이전트가 대신해주는 셈입니다.

## 배운 점

- 커밋 메시지 컨벤션이 콘텐츠 자동화의 품질을 좌우했습니다
- 완전 자동보다 반자동이 현실적이고 결과물 품질도 높았습니다
- 글의 시작점을 만들어주는 것만으로도 블로그 작성 빈도가 크게 올라갔습니다
