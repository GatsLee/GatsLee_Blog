# Mermaid 파서 62개 변형 전부 잡기

**카테고리:** troubleshooting
**태그:** Mermaid, parsing, regex, MDX, troubleshooting
**프로젝트:** one-by-one-cs

---

## 요약

CS 학습 플랫폼에서 Mermaid 다이어그램이 절반만 렌더링되는 버그를 추적했습니다. 원인은 파서가 62가지 flowchart 변형 중 31개를 놓치고 있었던 것이었습니다.

---

## 증상

MDX 파일에 Mermaid 코드 블록을 넣었는데, 어떤 건 예쁘게 렌더링되고 어떤 건 코드 텍스트 그대로 노출되었습니다. 처음에는 MDX 파싱 문제인 줄 알았습니다.

## 원인 추적

렌더링되는 것과 안 되는 것을 하나씩 비교해봤습니다. 공통점이 보이기 시작했습니다.

`graph TD`와 `graph LR`은 잘 되는데, 나머지 변형들이 문제였습니다.

- `graph TB`, `graph BT`, `graph RL` — 방향 변형
- 선행 빈 줄이 있는 경우 — 파서가 첫 줄에서 `graph` 키워드를 기대
- `direction TB` — 서브그래프 내부 방향 지시자
- `-.-` — 화살표 없는 점선
- `A -- "label" --> B` — 인라인 따옴표 레이블
- `A -- 5 --- B` — 인라인 숫자 레이블
- 중복 `graph TD` 선언이 있는 경우

전체 문서에서 Mermaid 블록을 추출해보니 62개였고, 그중 31개만 렌더링되고 있었습니다.

## 수정

각 변형에 대응하는 regex 패턴을 추가했습니다. 가장 까다로웠던 건 인라인 레이블 구문이었습니다.

```
# 기존: 화살표만 처리
A --> B
A -.-> B

# 추가: 인라인 레이블
A -- "label" --> B
A -- 5 --- B
A -.- B
```

선행 빈 줄 문제는 `trim()` 한 줄로 해결되었습니다. 중복 `graph` 선언은 첫 번째만 파싱하고 나머지는 무시하도록 했습니다.

```
수정 전: 31/62 렌더링
수정 후: 62/62 렌더링
```

## MDX hydration 에러도 같이 수정

디버깅하다가 hydration mismatch 에러도 발견했습니다. `<details><summary>` HTML 블록이 MDX에서 `<p>` 태그 안에 들어가고 있었습니다. HTML 스펙상 `<p>` 안에 블록 요소가 올 수 없어서 서버/클라이언트 렌더링이 달라졌습니다.

13개 MDX 파일에서 `<details>` 블록 전후에 빈 줄을 추가해서 블록 레벨로 인식하게 했습니다.

## 배운 점

- Mermaid 공식 문서에는 나와 있지 않은 변형이 꽤 많았습니다. 실제 사용 케이스를 전수 조사해야 했습니다
- 파서를 만들 때 "잘 되는 케이스"만 보면 절반을 놓칩니다. 전체 데이터에 대해 돌려봐야 했습니다
- MDX에서 HTML 태그를 쓸 때는 반드시 전후에 빈 줄을 넣어야 블록 레벨로 처리된다는 걸 배웠습니다
