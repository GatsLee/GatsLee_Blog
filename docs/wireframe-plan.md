# GatsBlog 와이어프레임 구성

Figma 상세기획 파일에 제작한 와이어프레임의 화면 목록과 구성. 로컬에서 실제로 돌아가는 화면을 브라우저로 확인한 뒤, 그 디자인 언어를 그대로 재현했다.

| 항목 | 값 |
|------|-----|
| 파일 | [GatsBlog 상세기획](https://www.figma.com/design/wsLPU5JDsN67AAutcUBGeO/GatsBlog-%EC%83%81%EC%84%B8%EA%B8%B0%ED%9A%8D) |
| File Key | `wsLPU5JDsN67AAutcUBGeO` |
| 페이지 | `wireframe(web)` (0-1), `wireframe(mobile)` (1-2), `components(local)` |
| 캔버스 폭 | web 1440px, mobile 390px |
| 기준 화면 | `http://localhost:4000` 실측 (2026-09-07) |

## 제작 경위

1차본은 Simple Design System의 마케팅용 Hero·Card Grid·Panel을 그대로 조립해 만들었으나, GatsBlog의 실제 디자인 언어와 맞지 않아 폐기했다(2026-09-07 삭제 완료). 현재 파일에 남은 것은 실측 기반 2차본 한 벌뿐이다.

## 탭 구조

홈 `TopNav`의 `navItems` 기준. 실제 라벨은 한글이다.

| 모듈 | 탭 라벨 | 라우트 | web | mobile |
|------|---------|--------|-----|--------|
| `HOM` 홈 | 홈 | `/` | 1 | 2 |
| `PRD` 프로덕트 | 만든 것 | `/products`, `/products/[slug]` | 5 | 5 |
| `PST` 포스트 | 포스트 | `/insights`, `/insights/[slug]` | 3 | 3 |
| `ADM` 관리자 | 비노출 | `/login`, `/admin`, `/write` | 20 | 2 |
| `BOT` AI 챗봇 | 전역 오버레이 | ASK GATS | 3 | 3 |
| `SYS` 공통 | — | — | 1 | 1 |

화면 코드는 `IA_{모듈코드}_{화면코드}` 형식이고, 화면코드는 레벨마다 2자리씩 늘어난다(1레벨 3자리 → 5 → 7 → 9 → 11). 하위가 없으면 거기서 끝난다. 전체 화면 목록은 **[`docs/ia.md`](./ia.md)**.

web 33개 + mobile 16개 = 49개 프레임(+ 웹의 `TPL_이미지슬롯` 템플릿). 각 화면의 헤더는 해당 탭이 활성(검정 + 밑줄) 상태로 override돼 있다.

**모바일 공개 영역은 2026-09-10에 웹과 같은 골격으로 다시 지었다.** IA_HM_001은 히어로 → 핵심 프로덕트 3장 → 워크플로우 5단계 → 아카이브, IA_PD_001는 프로덕트 블록 9개(이미지 슬롯 + 요점 3줄 + 스택 칩), IA_PS_001는 프로덕트 카드 필터 2열 + 채워진 아티클 카드, IA_PS_002는 프로덕트 연결·같은 프로덕트 포스트 블록까지 웹과 같다. 스페이서 사각형은 전부 걷어내고 오토레이아웃 간격으로 바꿨다. **관리자는 아직 IA_AD_001·IA_AD_00201 둘뿐이라 웹(16개)과 벌어져 있다.**

프로덕트 상세(`IA_PD_002`)는 한 화면이고 타입별로 세 벌을 그린다. 앱(AlterCharge) / 웹(GatsBlog) / 에이전트(Alfred). 골격은 `개요 → 문제 → 핵심 기능 → 서비스 플로우`이고, 에이전트만 서비스 플로우가 핵심 기능에 흡수돼 셋이다.

케이스 스터디·이력서·소개는 이 파일에 프레임이 없다. 케이스는 글이 0건이라 IA에서 뺐고(`ia-redesign.md`), 이력서·소개는 아직 그리지 않았다. 커넥트(방명록)는 2026-09-09에 삭제했다 — 화면, 모바일 짝, 푸터 링크까지.

## CB_AI챗봇 (ASK GATS)

라우트가 아니라 전역 오버레이라서 별도 섹션으로 뺐다. 실측: 데스크톱은 **480×640** 패널이 우하단(우 28px, 하 24px)에 뜨고 플로팅 필은 사라진다. 모바일은 **전체화면(390×844)** 으로 덮는다.

| 화면 | 상태 | 구성 |
|------|------|------|
| IA_CB_00101 | 제안 | 헤더(아바타 + GATS + 초록 닷 + "보통 3초 안에 답합니다" + 최소화·닫기, 60px) / 인사 `안녕하세요, AI 챗봇 Gats입니다 :)` + 한 줄 설명 / 추천 질문 4개 세로 목록 / 하단 고지문 / 입력바 |
| IA_CB_00102 | 대화 | 헤더에 대화 지우기 추가 / 사용자 메시지는 검정 채움 말풍선 우측 정렬 / 답변은 모노 `ASSISTANT` 라벨 아래 말풍선 없는 본문 |
| IA_CB_00103 | 생성 중 | 점 3개 + `생성 중` 표시 / 본문 자리 스켈레톤 3줄 / 입력바 비활성(플레이스홀더 "답변을 생성하는 중입니다") |

배경 화면 없이 패널만 그린다. 대화 상태의 답변은 로컬 ollama가 실제로 생성한 응답이다.

**2026-09-10 제안 상태 개편.** 카테고리 카드 5종 · 질문 10개를 추천 질문 4개로 줄였다. 근거는 셋이다. (1) `ChatMessage` 로그 165건에서 실제로 반복된 질문은 "어떤 프로젝트를 만들었나요?" 16회, "연락하고 싶어요" 12회 둘뿐이다. (2) 기존 카드에 있던 `ModelPulse`, `Seekr`는 프로덕트 목록에 없는 이름이라 물어도 답이 안 나온다. (3) 세션 138개 중 122개가 한 번 묻고 끝이라, 첫 화면에서 고를 게 많을수록 이탈이 는다. 남긴 질문은 넷이다.

1. 핵심 프로덕트는 어떤 것들이 있나요?
2. 비전공자에서 어떻게 프로그래밍으로 진로를 전환했나요?
3. 기획에서 멈추지 않고 직접 만드는 이유가 뭔가요?
4. 연락하고 싶어요

1번과 4번은 로그 상위 둘을 문장만 다듬은 것이고, 2·3번은 로그에 없지만 이 사이트가 무엇을 증명하려는 곳인지를 먼저 말해주는 질문으로 넣었다. 기술 스택·홈서버 질문은 프로덕트 상세에 이미 다 적혀 있어 뺐다. 챗봇 이름은 `GATS LAB AI`에서 `GATS`로 줄였다.

레이아웃은 최근 상담 위젯(채널톡 알프, Intercom Fin) 관행을 따랐다. 카드 그리드 대신 세로 목록, 3~4개 이내, 자유 입력은 항상 열어두고, 헤더에 응답 시간을 적어 기대치를 먼저 맞춘다. 하단 "AI가 답합니다. 정확하지 않을 수 있어요."는 입력바 바로 위에 붙는다.

모바일 패널(`유닛_챗패널_mobile`)은 아직 옛 카드 5종 구성이다.

## AD_관리자 — 시각 언어가 다르다

공개 페이지는 그리드·모노·헤어라인인데, 관리자 화면은 **라운드 카드 + 알약 버튼 + 링(ring)** 의 앱 UI다. 문구도 영어다. 실측(로그인 후)으로 확인한 내용이다.

**IA_AD_00201 관리자 대시보드**
- 헤더: 톱니 아이콘 + `Admin Dashboard` + `Manage your posts, comments, and guestbook entries`
- 탭 8개(알약, 활성은 검정 채움 + 2px ring): `Posts` `Comments` `Guestbook` `Chat` `RAG` `FAQ` `About` `Resume` — 앞 3개는 아이콘 있음
- 카테고리 필터 알약 5개(대문자): `JOURNAL` `PRODUCT` `AGENT` `BUILD` `CASE`
- 테이블(라운드 12px 카드): 체크박스 / `TITLE`(+ 댓글 수) / `CATEGORY` 칩 / `STATUS` 칩(Draft 분홍, Published 회색) + 핀 / `DATE` / `ACTIONS`(편집·삭제)
- 테이블 푸터: `1-10 of 19` + 페이지네이션. 모바일은 컬럼을 제목·상태만 남기고 접는다

**포스트 작성 진입** — 별도 카테고리 선택 화면은 2026-09-09에 없앴다. IA_AD_00203의 `+ 포스트 작성`을 누르면 그 아래 드롭다운(저널 / 빌드 로그)이 열리고, 고르면 바로 에디터로 간다. 열린 상태는 `IA_AD_0020302_포스트작성_드롭다운`.

**IA_AD_0020301 글작성 — 에디터** (카테고리 선택 후)
- 서브 헤더: `POST / EDITOR` 모노 / 우측 `Public`(초록) + 공개 아이콘 + 검정 `COMMIT` 버튼
- 본문: `New Page` 대형 회색 플레이스홀더 / 날짜 선택 칩 + `● Public` 칩 / 헤어라인 / `Enter text or type '/' for commands`
- 우측 사이드바(좌측 1px 경계): `PAGE SETTINGS` — Slug / Tags / Description, 헤어라인, `TABLE OF CONTENTS` + `Add headings to see TOC`
- 하단 상태바: `Words: 0 · Reading: ~1 min · ● Live Sync`
- 글로벌 푸터·챗 버튼 없음

## 화면별 구성

**IA_HM_001 홈** — 헤더 / 히어로(모노 eyebrow + 56px 명제 + 리드 + CTA 2개 ‖ 지표 3행: 80%·3·99%+) / 홈서버 상태(설명 ‖ 터미널 패널 UPTIME·CONTAINERS·RAM·DISK) / 포스트 ‖ 만든 것(프로덕트·에이전트 2열, 상태 닷 + 모노 상태) / 푸터. mobile은 전부 1열로 쌓인다.

**IA_HM_00101 메뉴 열림** — 전체화면 메뉴, 탭 24px, 활성 탭만 검정.

**IA_PD_001 프로덕트 목록** — 브레드크럼 / 타이틀 / 필터 탭(전체 6·프로덕트 3·에이전트 3) / 카드 그리드 3열(web) — 상태칩 + 타입칩 + 날짜 / 이름 / 요약 / 기술칩 / 자세히 보기.

**IA_PD_00101 필터 드롭다운** — IA_PD_001의 필터가 열린 상태만 따로 그린 보조 화면.

**IA_PD_002 프로덕트 상세** — 타입별로 세 벌이다. 공통 골격은 `섹션_개요(뒤로가기·카테고리+도장·제목+한줄 요약+액션 버튼 2개·메타 4칸·대표 이미지) → 문제(서술 + 근거 카드) → 핵심 기능 → 서비스 플로우`. 에이전트는 마지막 섹션이 핵심 기능에 합쳐져 셋이다. 결과(산출·판단·한계) 섹션은 2026-09-09에 뺐다.

| 사례 | 프로덕트 | 핵심 기능 | 문제 옆 근거 | 서비스 플로우 |
|------|------|-----------|--------------|---------------|
| 앱 | AlterCharge | SCENARIO — 단계마다 모바일 목업 최대 2컷(440×360) | 인용문(관찰) + 수치 + 요약 | 별도 섹션 · Figma 임베드 |
| 웹 | GatsBlog | SCREENS — 단계마다 웹 목업 1컷(640×360) | 인용문(로그 분석) + 수치 + 요약 | 별도 섹션 · Figma 임베드 |
| 에이전트 | Alfred | PIPELINE — Figma 임베드 + 목업 없는 4단계 | 요약 + 수치 · 인용문 없음 | **핵심 기능에 흡수** |

에이전트만 섹션이 셋이다. 화면 흐름이 곧 서비스 플로우라 두 섹션이 같은 것을 두 번 말했다. 그래서 PIPELINE 헤더 아래에 임베드를 바로 놓고 별도 섹션을 없앴다.

근거는 유형을 골라 조립한다. 인용문 1 · 수치 2 · 요약 한 줄 1이 상한이고, 인용문에는 수집 방법(대면 인터뷰 · 관찰 · 설문 · 로그 분석 · 문헌) · 대상 · 기간이 붙는다.

메타 4칸은 `기간 · 역할 · 유형 · 타겟`이다. 라벨은 20px A63D2F, 값은 13px. 역할은 인원까지 합쳐 `기획·개발 · 1인`으로 찍는다. 유형 값 집합은 서비스 / 자체 도구 / 사내 과제 / 외주.

**IA_PS_001 포스트 목록** — 브레드크럼 / 타이틀 + 건수 / 프로덕트 카드 필터(카드마다 이름 + 포스트 수 + 태그 3개, 최근 포스트순 정렬) / 연도 마커 / 포스트 카드(좌측 65px 월 거터 20px + 배경 채운 카드: 제목 → 한 줄 결론 → `날짜 · 유형 · 프로덕트` 메타 한 줄, 우측 끝 태그). 프로덕트명만 A63D2F. 읽기시간과 언어 표시는 뺐다.

**IA_PS_002 포스트 상세** — 뒤로가기 / 제목 / 메타 / 태그 / AI 요약 박스 / 본문 / **프로덕트 연결 카드**(PRODUCT + 프로덕트명 + 상세 보기) / **같은 프로덕트의 다른 포스트** / 헤어라인 / 댓글.

**IA_AD_001 로그인** — 중앙 폰 아이콘 + GATS_LAB / 테두리 카드(ADMIN AUTHENTICATION, USERNAME, PASSWORD, AUTHENTICATE 검정 버튼). 푸터만, 챗 버튼 포함.

### 그리지 않는 화면

**이력서** — 화면을 그리지 않는다. 헤더의 `이력서 ↗`는 새 탭에서 PDF를 여는 링크다. 그래서 네비에 외부 링크 화살표가 붙어 있다.

**소개** — 2026-09-10에 IA에서 뺐다. 라우트(`/about`)와 `SiteConfig.about_ko` 데이터는 코드에 남아 있고, 화면·네비·모바일 전체 메뉴에서만 제거했다.

**케이스 스터디** — 글이 0건이라 뺐다(`ia-redesign.md`).

**다크 모드** — 제작하지 않는다.

와이어프레임이 코드보다 앞선다. 네비·라우트 불일치(`/cases` `/connect` `/about`이 코드에 남아 있고 `TopNav.navItems`가 6개인 것)는 나중에 코드에 반영한다.

## 네이밍 규칙

- 화면 프레임: `IA_{모듈코드}_{화면코드}_{화면명}`. 같은 화면은 web·mobile 페이지에서 같은 코드를 쓴다. 체계는 [`docs/ia.md`](./ia.md).
- 화면을 나누는 큰 덩어리: `섹션_{역할}`
- 섹션 안에서 의미로 묶은 덩어리: `블록_{역할}`
- 되풀이되는 완결 단위(카드·버튼·칩·도장·탭·입력): `유닛_{역할}`
- 더 못 쪼개는 낱개(텍스트·도형): `요소_{역할}`
- Figma 기본 이름 잔재: 세 페이지 모두 0건.

2026-09-10에 `SEC_`/`CMP_`/`EL_` 세 접두사를 위 네 가지로 바꿨다(총 12,302개). 판정 기준도 노드 타입에서 역할로 옮겼다 — 이전 규칙은 GROUP/FRAME이면 무조건 `SEC_`였는데, 오토레이아웃을 쓰면 의미 단위마다 프레임이 생겨서 실제로는 1,773건이 `EL_` FRAME으로 어긋나 있었다. 규칙은 `~/.claude/skills/DP_figma-layer-naming`.
