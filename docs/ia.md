# GatsBlog IA

화면 식별 체계와 전체 화면 목록. 와이어프레임 프레임 이름, 기획 문서, 이후 코드의 라우트 주석이 모두 이 코드를 쓴다.

## 식별 체계

```
IA_{모듈코드}_{화면코드}_{화면명}
```

화면코드는 레벨이 깊어질 때마다 2자리씩 늘어난다. **하위가 없으면 거기서 끝난다. 0으로 채우지 않는다.**

| 레벨 | 자릿수 | 예시 | 뜻 |
|------|--------|------|-----|
| 1 | 3 | `IA_HM_001` | 모듈의 주 화면 |
| 2 | 5 | `IA_HM_00101` | 주 화면의 하위 화면·탭·상태 |
| 3 | 7 | `IA_HM_0010101` | 그 아래 |
| 4 | 9 | `IA_HM_001010101` | 그 아래 |
| 5 | 11 | `IA_HM_00101010101` | 그 아래 |

각 레벨의 번호는 그 자리에서 형제끼리 `01`부터 센다. 맨 오른쪽 두 자리가 현재 레벨의 순번이고, 왼쪽은 부모의 경로다.

`IA_AD_002020101_프로덕트편집_앱`을 끊어 읽으면 `002 · 02 · 01 · 01`이다. 관리자(AD)의 두 번째 주 화면(대시보드) → 두 번째 탭(프로덕트) → 첫 번째 하위 화면(편집) → 첫 번째 변형(앱).

레벨 1이 3자리인 이유는 모듈 하나가 주 화면 100개를 넘을 일이 없고, 중간 삽입 여지를 남기기 위해서다. 반면 하위 레벨은 형제가 열 몇 개를 넘지 않아 2자리로 충분하다.

(+) 코드 길이만 봐도 몇 층 아래인지 즉시 읽힌다
(-) 화면을 다른 부모 밑으로 옮기면 코드가 바뀐다. 라우트가 바뀌는 수준의 변경에서만 일어나므로 감수한다

## 한 화면의 여러 사례

같은 화면에 다른 내용이 들어갈 뿐인 경우는 코드를 나누지 않는다. 코드는 그대로 두고 화면명 뒤에 사례 이름을 붙여 프레임을 여러 벌 그린다.

| 코드 | 사례 | 무엇이 다른가 |
|------|------|---------------|
| `IA_PD_002` | 앱 / 웹 / 에이전트 | 섹션 구성이 타입마다 달라진다(에이전트는 서비스 플로우가 핵심 기능에 흡수) |
| `IA_AD_0020201` | 앱 / 웹 / 에이전트 | 타입을 고르면 핵심 기능 폼의 필드가 바뀐다 |

코드를 나누는 기준은 **다른 화면인가**다. 필터가 열린 상태, 빈 상태, 로그인 실패처럼 화면 구조 자체가 달라지면 코드를 나누고, 같은 구조에 값만 다르면 나누지 않는다.

## 그리지 않는 화면

| 화면 | 왜 없나 |
|------|---------|
| 케이스 스터디 | 글이 0건이라 IA에서 뺐다 |
| 이력서 | 클릭하면 브라우저 새 탭에서 PDF가 열린다. 화면이 아니다 |
| 소개 | 2026-09-10에 IA에서 뺐다. 라우트와 `SiteConfig.about_ko`는 코드에 남아 있다 |
| 커넥트(방명록) | 2026-09-09에 삭제 |
| 다크 모드 | 별도 프레임을 그리지 않는다 |

`TPL_이미지슬롯`, `TPL_근거블록`은 화면이 아니라 템플릿이라 IA에 넣지 않고 `TPL_` 접두사를 유지한다.
